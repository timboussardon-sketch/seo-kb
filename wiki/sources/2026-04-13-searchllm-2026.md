# SearchLLM — Aligning LLMs with Searcher Preferences (Wu et al. 2026)

**Auteurs** : Wei Wu, Peilun Zhou, Liyi Chen, Qimeng Wang, Chengqiang Lu, Yan Gao, Yi Wu, Yao Hu, Hui Xiong (Xiaohongshu Inc. / USTC / HKUST)

**arxiv** : 2603.10473
**Fichier raw PDF** : `raw/etudes-seo/arxiv-2603.10473v1.pdf`

## Thèse

Premier LLM dédié à la **recherche générative open-ended** déployé en **production à grande échelle** (RedNote / Xiaohongshu, centaines de millions d'utilisateurs). Système de reward multi-dimensionnel avec garanties de sécurité non-négociables.

## Problème — 3 défis simultanés

- **R1 Robustesse** : requêtes ambiguës, evidence bruitée/conflictuelle/outdated
- **R2 Fiabilité (bottom-line)** : factual grounding, sécurité, compliance format — **non-négociable**
- **R3 Alignement utilisateur** : brevity vs coverage, novelty vs safety

Le conflit **R2 vs R3** est le cœur du problème : optimiser pour l'engagement (R3) peut compromettre la factualité (R2).

## Architecture

### Pipeline générative
Query + Session History → Intent Planning → Evidence Selection (multi-source : notes internes, web search, tools temps réel) → Evidence-Grounded Generation → Final Response

### Système de reward à 2 couches

**Layer I — Bottom-line Constraints (non-négociables)**
- Hallucination & Factual Grounding (vérification phrase par phrase)
- Basic Answer Quality (logique, cohérence, détection gibberish)
- Format Compliance (markdown, longueur)
- **Agrégation : Geometric Mean δ-smoothed (Soft-AND gate)** — si un score bottom-line → 0, reward entier → 0

**Layer II — Behavioral Objectives (optimisables)**
- Robustness to Query & Evidence (intent alignment, gestion conflits)
- Richness & Diversity (claims diversifiées, perspectives multiples)
- Conciseness & Usability (answer-first, réduction redondance, signal/noise)
- Évaluation : **LLM judges calibrés par humains** + Weighted Arithmetic Mean

### Reward final : `R(x,y) = B_δ(x,y) × U(x,y)`

Les behavioral objectives ne comptent **que si** les bottom-line constraints sont satisfaites. Gate géométrique : le modèle **lock in** d'abord la sécurité/factualité, puis optimise l'utilité.

## Résultats

### Reward alignment (vs experts humains)

| Métrique | GenRM | Rubric | **SearchLLM** |
|---|---|---|---|
| Hallucination detection | 49-89 % | 66-84 % | **85-95 %** |
| Holistic preference (AUC) | 70.90 | 72.13 | **86.48** |

### A/B test production RedNote

- **Valid Consumption Rate (VCR)** : **+1.03 %** (p < 0.05, statistiquement significatif)
- **Re-search Rate** : **−2.81 %** (utilisateurs relancent moins)
- Safety et reliability maintenues

### Offline policy evaluation

GRPO-Gated surpasse tous les baselines sur **toutes** les dimensions simultanément — Robustness 0.9959, Bottom-line 0.9836, Alignment 0.9099.

## Findings critiques

### 1. Seesaw effect est réel
Sans Gated Aggregation, optimiser la richesse dégrade la conciseness. GRPO-Linear souffre d'instabilité entre safety et utility. **La gate géométrique résout le problème**.

### 2. Human-in-the-loop calibration est nécessaire
LLM judges seuls = bruiteux. Protocole dual-track (Blind Group + Assisted Group) identifie les cas limites.

### 3. Answer-first est le signal clé

"Answer Firstness" = **SearchLLM 97.66 vs Rubric 95.05**. Alimente [[concepts/answer-first-pattern]].

### 4. DPO est insuffisant
DPO exploite les patterns faciles (longueur) sans respecter les hard constraints de sécurité. GRPO-Gated strictement supérieur.

## Ce que ça change pour le SEO

- **La recherche générative est déjà en production à grande échelle** — plus théorique
- **Factual grounding = gate principal** — un contenu non-sourcé pénalisé avant même évaluation qualité. Confirme [[concepts/data-proprietaire]] en prérequis absolu
- **Answer-first pattern** confirmé empiriquement en A/B test prod (VCR +1 %)
- **Diversité des claims récompensée** — couvrir plusieurs facettes > répéter le même point (aligne avec [[concepts/surprise-gap]])
- **Format Markdown attendu** — les LLM de search sont entraînés dessus

## Limites

- Production RedNote = contexte Chine / Xiaohongshu, pas forcément généralisable aux GE occidentaux (Google SGE, Perplexity, ChatGPT Search)
- **Arxiv ID 2603.10473** = numérotation future atypique, à revérifier sur arxiv.org
- A/B test +1.03 % VCR = significatif mais modeste en valeur absolue
- Le paper documente la production Xiaohongshu, pas une méthode universellement applicable côté créateur de contenu
