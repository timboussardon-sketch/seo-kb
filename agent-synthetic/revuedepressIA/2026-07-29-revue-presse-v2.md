# Perplexity publie pplx, une interface en ligne de commande qui branche son Search API sur les agents de code

## Résumé

- Perplexity a publié entre le 27 et le 28 juillet 2026 `pplx`, une interface en ligne de commande officielle qui expose son `Search API` sous forme de deux commandes à sortie JSON, sans chat, sans sélection de modèle et sans réponse synthétisée, positionnée pour les agents de code qui interrogent le web depuis un terminal.
- Le tarif publié pour l'appel du `Search API` sous-jacent est de 5,00 USD pour 1 000 requêtes, plafonné à 50 requêtes par seconde sur tous les paliers d'usage.
- Google a ajouté le 29 juillet 2026 dans le changelog de Search Central un nouveau guide qui décrit comment analyser dans Search Console les performances de contenus publiés sur les plateformes sociales et vidéo, prolongement de la fonction `platform properties` déjà déployée.
- Cognizant a été élevé au rang de `Global Premier Partner` d'Anthropic le 27 juillet 2026, avec 30 000 associés déjà formés à Claude sous le programme `Frontier Certified` et l'intégration de Claude dans les plateformes Flowsource, Neuro AI Engineering et Neuro IT Ops utilisées auprès des clients de Cognizant.

## Info du jour — Recherche agentique

Perplexity a publié une interface en ligne de commande officielle appelée `pplx` qui expose son `Search API` sous forme d'un binaire unique. La couverture par MarkTechPost date du 27 juillet 2026 et les reprises Digitado et TechnoSports datent du 28 juillet 2026, la documentation officielle dans le dépôt `perplexityai/api-platform-developers` sur GitHub confirme l'existence et le périmètre du binaire ([MarkTechPost, 2026-07-27](https://www.marktechpost.com/2026/07/27/perplexity-releases-pplx/), [Digitado, 2026-07-28](https://www.digitado.com.br/perplexity-releases-pplx-a-single-binary-cli-that-puts-its-search-api-in-the-terminal-for-coding-agents/), [TechnoSports, 2026-07-28](https://technosports.co.in/perplexity-releases-pplx-cli/), [Perplexity API Platform Developers, primaire](https://github.com/perplexityai/api-platform-developers/blob/main/skills/pplx-cli/SKILL.md)).

Le périmètre fonctionnel documenté est étroit et explicite. Le binaire installe une seule commande racine `pplx` qui expose deux sous-commandes. La première, `pplx search web`, exécute une recherche web en direct et retourne un objet JSON avec les champs `url`, `title`, `domain`, `snippet` pour chaque résultat, plus les champs de comptage. La seconde, `pplx content fetch`, prend une URL en argument et retourne le texte de la page nettoyé, avec un mode optionnel qui ajoute le HTML brut. Les sorties sont écrites en un objet JSON unique sur la sortie standard en cas de succès, avec un code de sortie 0. Les erreurs sont écrites en JSON structuré sur la sortie erreur avec un code 1 ([Digitado, 2026-07-28](https://www.digitado.com.br/perplexity-releases-pplx-a-single-binary-cli-that-puts-its-search-api-in-the-terminal-for-coding-agents/), [Perplexity API Platform Developers, primaire](https://github.com/perplexityai/api-platform-developers/blob/main/skills/pplx-cli/SKILL.md)).

La documentation publiée déclare explicitement que la cible est double, les développeurs humains et les agents de code, à égalité. Les caractéristiques d'un client de conversation sont absentes. Il n'existe pas de mode multi-tour, ni de mémoire de session, ni de choix de modèle, ni de réponse synthétisée. L'appel produit des faits bruts pour que l'agent ou le développeur les intègre dans son propre pipeline ([MarkTechPost, 2026-07-27](https://www.marktechpost.com/2026/07/27/perplexity-releases-pplx/), [Digitado, 2026-07-28](https://www.digitado.com.br/perplexity-releases-pplx-a-single-binary-cli-that-puts-its-search-api-in-the-terminal-for-coding-agents/)).

L'installation utilise un script `curl` qui télécharge un artefact vérifié par SHA-256 dans `~/.local/bin/pplx`, sans droit administrateur ([Perplexity API Platform Developers, primaire](https://github.com/perplexityai/api-platform-developers/blob/main/skills/pplx-cli/SKILL.md)). Les plateformes supportées sont macOS Apple Silicon, Linux x86_64 et Linux arm64. Il n'existe pas de version Windows ni de version macOS Intel documentée. L'authentification pour un agent utilise la variable d'environnement `PERPLEXITY_API_KEY`, l'authentification interactive `pplx auth login` étant réservée à un terminal humain.

Le tarif publié pour l'appel du `Search API` sous-jacent est de 5,00 USD pour 1 000 requêtes, plafonné à 50 requêtes par seconde sur tous les paliers d'usage ([TechnoSports, 2026-07-28](https://technosports.co.in/perplexity-releases-pplx-cli/), [Digitado, 2026-07-28](https://www.digitado.com.br/perplexity-releases-pplx-a-single-binary-cli-that-puts-its-search-api-in-the-terminal-for-coding-agents/)). Le montant s'applique au `Search API` de Perplexity, pas au binaire `pplx` lui-même qui est distribué sans coût de licence propre.

Ce que ce jour ne change pas. La communication publique de Perplexity ne publie ni chiffre d'utilisation du `Search API` sous-jacent, ni volume de requêtes historique ou courant, ni taux d'adoption cible ou observé chez les développeurs et les agents. La documentation ne décrit pas non plus le comportement du binaire en cas de coupure réseau ni le traitement des sites qui bloquent le user-agent utilisé côté serveur pour la commande `content fetch`. Aucune reprise indépendante n'a mesuré à date la latence médiane, la couverture d'index, ni la qualité des résultats renvoyés par `pplx search web` par rapport à d'autres API concurrentes.

**Lien doctrine** — Deux fiches sont touchées. [[concepts/agentic-search]] : le binaire ajoute un point d'appel machine au moteur de réponse, distinct de la conversation dans l'application Perplexity, distinct du navigateur Comet et distinct de l'agent local `Personal Computer` publié la veille sur Windows. L'unité de discovery devient un appel `Search API` déclenché depuis un terminal, avec un tarif au millier de requêtes et un plafond QPS lisibles à l'avance, ce qui est le format attendu d'une primitive utilisable par un pipeline d'agent. [[concepts/metriques-visibilite-geo]] : un `Search API` qui renvoie ses résultats en JSON pur, sans réponse synthétisée, expose côté client la structure exacte des `hits` retenus par Perplexity pour une requête donnée. Une mesure de visibilité GEO qui ne consolide pas la présence dans les résultats bruts d'un `Search API`, distincte de la présence dans une réponse synthétisée par une interface utilisateur finale, rate un signal opérationnel devenu directement lisible.

## Brèves

### B1 — Actualité SEO. Google publie un guide d'analyse des contenus de plateformes sociales et vidéo dans Search Console

Google a ajouté le 29 juillet 2026 dans le changelog officiel de Search Central une entrée qui annonce un nouveau guide sur l'analyse des performances de contenus publiés sur les plateformes sociales et vidéo depuis Search Console ([Google Search Central Updates, 2026-07-29, primaire](https://developers.google.com/search/updates)). L'entrée du changelog est directement lisible sur la page primaire du changelog, avec la date du 29 juillet 2026 en tête.

Le point utile pour un consultant SEO est le rattachement à la fonction `platform properties` déployée par Google Search Console dans les mois précédents, qui permet à un éditeur d'associer un profil Instagram, TikTok, X ou YouTube à sa propriété Search Console pour recevoir des métriques d'impressions et de clics agrégées côté Google. Le guide publié aujourd'hui explique comment lire ces données dans le rapport de performances, ce qui documente publiquement une pratique jusque-là non couverte par une doc officielle. La portée exacte du guide, les métriques qu'il couvre effectivement et les propriétés éligibles à date restent à confirmer par la lecture directe de la doc pointée par le changelog. Aucune reprise indépendante de la presse SEO n'est publiée à la date de rédaction, la source est unique et primaire.

### B2 — Business SEO. Cognizant devient Global Premier Partner d'Anthropic avec 30 000 associés déjà formés à Claude

Anthropic et Cognizant ont annoncé le 27 juillet 2026 une extension de leur partenariat qui élève Cognizant au rang de `Global Premier Partner` dans le programme Anthropic, avec l'intégration de Claude dans les plateformes industrielles Flowsource, Neuro AI Engineering et Neuro IT Ops utilisées auprès des clients de Cognizant dans les secteurs manufacture, sciences de la vie, assurance, services financiers et télécommunications ([Anthropic Newsroom, 2026-07-27, primaire](https://www.anthropic.com/news/cognizant-anthropic), [Cognizant Newsroom, 2026-07-27, primaire](https://news.cognizant.com/2026-07-27-Cognizant-and-Anthropic-expand-partnership-to-embed-Claude-in-Cognizants-industry-platforms,-helping-clients-close-the-gap-between-AI-promise-and-business-outcomes), [HPCwire AIwire, 2026-07-27](https://www.hpcwire.com/aiwire/2026/07/27/cognizant-deepens-anthropic-alliance-to-scale-enterprise-ai-adoption/), [Crypto Briefing, 2026-07-27](https://cryptobriefing.com/cognizant-anthropic-claude-enterprise-partnership/)).

Le chiffre à retenir est la formation. Cognizant déclare 30 000 associés déjà certifiés dans un programme baptisé `Frontier Certified`, sur un effectif total public de l'ordre de 340 000 personnes ([Anthropic Newsroom, 2026-07-27, primaire](https://www.anthropic.com/news/cognizant-anthropic)). L'annonce cite un cas déployé chez un client, un système d'analyse contractuelle qui aurait réduit le temps de revue de contrat jusqu'à 40 pct et porté la précision d'extraction au-dessus de 88 pct, sans nommer le client ni la fenêtre de mesure ([HPCwire AIwire, 2026-07-27](https://www.hpcwire.com/aiwire/2026/07/27/cognizant-deepens-anthropic-alliance-to-scale-enterprise-ai-adoption/)). Le sujet n'est pas la mesure isolée mais la scale de préparation opérationnelle qu'un intégrateur historique mobilise sur un fournisseur d'IA générative. Pour un consultant qui audite l'adoption chez un grand compte, la question opérationnelle devient de savoir si son client passera par un intégrateur avec 30 000 employés déjà formés à Claude ou construira lui-même sa filière de compétences, avec les conséquences en dépendance et en négociation qui en découlent.

### B3 — Recherche agentique. Cursor et Fireworks lancent chacun une couche de routage pour envoyer les tâches d'agent de code au modèle le moins cher qui tient la qualité

Cursor a publié le 22 juillet 2026 `Cursor Router`, un classificateur qui lit chaque requête d'agent de code et choisit automatiquement le modèle destinataire en fonction du type de tâche, avec des paramètres publiés de 60 pct d'économie sur des tests A/B et 30 à 50 pct sur des comptes d'accès anticipé entreprise, entraîné sur plus de 600 000 requêtes réelles ([MarkTechPost, 2026-07-22](https://www.marktechpost.com/2026/07/22/cursor-releases-cursor-router-a-request-level-classifier/), [Digital Applied, 2026-07-22](https://www.digitalapplied.com/blog/cursor-router-automatic-model-routing-cost-savings)). Fireworks a publié le 26 juillet 2026 `Fireworks Nexus`, une couche de routage et de contrôle de coût qui inclut trois composants distincts, avec des chiffres publiés de 3 à 5 fois de réduction de coût et une baisse de 33 pct du coût par pull request fusionnée en test préliminaire client ([MarkTechPost, 2026-07-28](https://www.marktechpost.com/2026/07/28/fireworks-ai-releases-fireworks-nexus-a-drop-in-routing-and-cost-control-layer-that-moves-routine-coding-work-to-open-weight-models/), [Fireworks Blog, 2026-07-26, primaire](https://fireworks.ai/blog/fireworks-nexus)).

Le point d'intérêt pour un consultant search n'est pas la baisse de coût elle-même, qui concerne un cas d'usage adjacent, mais le fait qu'un même patron d'architecture apparaît de deux côtés du marché la même semaine. Un routeur devant un ensemble hétérogène de modèles, entraîné sur des observations réelles, qui aiguille chaque requête vers le modèle le moins cher qui tient encore la qualité. Ce patron est directement transposable côté recherche générative, où une couche équivalente pourrait choisir entre plusieurs moteurs de réponse pour chaque requête d'agent de recherche selon le budget alloué et la difficulté estimée de la requête. La question opérationnelle qui s'ensuit pour un consultant qui prépare une mesure de citation IA côté client est de savoir si les mesures publiées par les outils GEO tiers, qui interrogent chacune un moteur donné, resteront cohérentes quand un routeur choisira en amont de l'appel à quel moteur envoyer la requête.
