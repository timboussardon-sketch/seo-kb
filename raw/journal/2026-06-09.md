# Journal — 2026-06-09

> Jalon : **Leexi devient le premier client à recevoir un système IA complet**, pas juste des livrables. Session de mise en place de l'architecture de livraison + réparation du questionnaire client.

## 🎯 Sujets traités

- **Dossier client Leexi structuré** (seo-kb) : création de `raw/organikk/clients/leexi/` avec fiche maître `leexi.md` (privée, ma strat) + transcript `leexi-call-2026-05-21.md` rapatrié depuis `raw/transcripts/`.
- **Architecture de livraison "système IA complet"** : 3 repos, frontière nette. `seo-kb` reste privé à vie ; `leexi-seo` (repo transférable, GitHub privé) porte leur data/cerveau/production ; `organikk-seo-pack` (GitHub privé) porte la doctrine + skills, en **vivant** (submodule synchronisé).
- **8 skills SEO portés et génériciss** dans le pack, synchronisés dans `leexi-seo` via submodule + symlink `.claude/skills`. Voix paramétrée sur `$VOIX_DIR` (jamais la voix perso de Tim).
- **STRATEGIE.md Leexi** : les 4 piliers Organikk (Surprise / Grounding / pSEO / AEO + data propriétaire) réécrits appliqués au notetaker Leexi.
- **voix-leexi v0** : voix de marque extraite du call de découverte (partielle, la voix client attend leurs calls de démo).
- **Questionnaire client réparé** (organikk-next, prod) : il postait vers Netlify Forms non détecté (POST 404, aucune réponse enregistrée), bascule sur table Supabase `client_questionnaire` + page `admin.html`. Vérifié end-to-end en prod.

## 💡 Idées & hypothèses émises

- Le moat de Tim n'est pas un skill isolé mais la mémoire qui compound entre tous les clients : on peut donc donner les skills et la doctrine à un client sans donner l'avantage, tant que `seo-kb` (tous les clients, le commercial, la voix perso) reste privé.
- La voix se paramètre, elle ne se cache pas : le pack apporte la méthode, `$VOIX_DIR` apporte le ton du client. (origine : Tim)

## ✅ Décisions prises

- **seo-kb ne se partage jamais.** Le système livrable est un repo dédié par client, transférable par ownership GitHub.
- **Skills vivants/synchronisés** (modèle retainer), pas snapshot figé : le client reste sur la dernière version de la doctrine via `git submodule update --remote`.
- **Doctrine basée sur le vrai seo-kb**, adaptée au client, pas reconstruite de mémoire.
- **Questionnaire confidentiel** : insert anon mais PAS de select anon sur la table Supabase, lecture admin via clé runtime (jamais commitée).

## 🔄 Pivots & changements de cap

- La query `transfert-vault-client` ne faisait qu'un **snapshot figé** (limite qu'elle notait elle-même). On passe au **pack vivant** synchronisé. C'est l'évolution de cette procédure.

## ❓ Questions ouvertes

- Au handover, donner au compte Leexi l'accès collaborateur au pack privé `organikk-seo-pack` (sinon leur `submodule update` échoue). À gérer le jour du transfert.
- Durcissement possible de l'admin questionnaire : passer la lecture par une edge function avec mot de passe, pour ne pas manipuler la clé service_role dans le navigateur.
- voix-leexi reste en v0 tant que Leexi n'a pas déposé de vrais calls de démo dans `data/calls/`.
